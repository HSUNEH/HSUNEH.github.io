Architecture구조

Problem문제

The audio team of 22 takes sound orders for more than 30 projects from 15 development studios. Each studio runs its own Jira, while the audio team's parts use Slack Lists, Notion and Trello. No tool held both.

When a studio's Jira changed, someone had to notice and copy it over by hand, and some changes slipped by. One project often involved several parts at once, and when work moved from one part to the next, as in mixing and mastering, handoffs got crossed. Studios also named and sized their schedules differently (an update version here, a milestone build there), so the audio team had no deadline axis of its own.

The first request was a Slack bot that tidies up incoming orders. Talking with the team, I found the hard part came after intake: splitting the work and managing deadlines. A bot built only to the request would have been one more bot nobody used.

오디오 조직 22명은 개발 스튜디오 15곳의 30개가 넘는 프로젝트에서 사운드 발주를 받습니다. 개발사는 저마다 Jira를 쓰고 오디오 조직의 파트들은 Slack 리스트·Notion·Trello를 따로 씁니다. 이 둘을 함께 담는 도구가 없었습니다.

개발사 Jira가 바뀌면 담당자가 직접 확인해 옮겨야 했고 바뀐 줄 모르고 지나가는 일도 생겼습니다. 한 프로젝트에 여러 파트가 나란히 붙고 믹스·마스터처럼 일이 파트를 건너 이어지면 인계가 엇갈렸습니다. 개발사마다 일정 이름과 단위가 달라서(어디는 업데이트 버전, 어디는 마일스톤 빌드) 오디오 조직 기준의 마감도 세울 수 없었습니다.

처음 받은 요청은 발주를 정리해 주는 Slack 봇이었습니다. 현업과 이야기해 보니 어려운 일은 접수보다 그 뒤, 일을 나누고 마감을 챙기는 쪽에 있었습니다. 요청대로 봇만 만들었다면 쓰이지 않는 봇이 하나 더 생겼을 겁니다.

Solution해결

I designed it to gather data from the tools people already used rather than replace them. Projects work differently, so instead of fixed features people set up their own properties, views and filters, as in Notion. A single value is edited in place without opening a detail panel, and actions that can be undone show an undo toast instead of a confirmation dialog.

The structure has three levels: project, work schedule, task. The work schedule level is new. It restates each studio's schedule on the audio team's terms.

Adding a label to a studio's Jira ticket brings the task in, keeps its title, deadline and status in sync, and files it under the right work schedule. Trello and Slack Lists are connected as well, and Outlook leave shows up on the timeline.

A Slack message shortcut has an LLM fill in a task draft, and a Slack bot answers DMs such as "What's due for me this week?". An MCP server registered on the company MCP gateway lets Claude look up and edit tasks. The first version, a conversational ordering bot, was removed in September 2026 and redesigned around message shortcuts.

When someone leaves an improvement request, headless Claude Code implements it and opens a pull request, and a person reviews and merges it. From August 2026 a member of the audio team co-built the screens with me. I also wrote the step-by-step guide, the introduction deck and a help chat.

기존 도구를 바꾸라고 하지 않고 데이터를 한곳에 모으는 축으로 설계했습니다. 프로젝트마다 일하는 방식이 달라서 기능을 고정하지 않고 노션처럼 사용자가 속성·보기·필터를 직접 구성하게 했습니다. 값 하나는 상세창을 열지 않고 그 자리에서 고치며 되돌릴 수 있는 동작에는 확인창 대신 실행 취소 알림을 띄웁니다.

구조는 프로젝트 › 업무 일정 › 일감의 3단입니다. 업무 일정은 개발사마다 다른 일정을 오디오 조직 기준으로 다시 세운 층입니다.

개발사 Jira 티켓에 라벨만 달면 일감이 들어오고 제목·마감·상태가 따라 바뀌며 맞는 업무 일정 아래로 자동 배치됩니다. Trello·Slack 리스트와도 연동했고 Outlook의 연차·반차는 타임라인에 표시됩니다.

Slack 메시지 숏컷을 누르면 LLM이 칸을 채운 일감 초안을 만듭니다. Slack 봇에게는 "이번 주 내 마감 뭐 있어?"처럼 DM으로 물을 수 있습니다. MCP 서버는 사내 MCP 게이트웨이에 등록해 Claude에서 일감을 조회·수정하게 했습니다. 처음 만든 대화형 발주 봇은 2026년 9월에 걷어내고 메시지 숏컷 방식으로 다시 설계했습니다.

현업이 개선 요청을 남기면 headless Claude Code가 구현해 PR까지 만들고 머지는 사람이 합니다. 화면은 2026년 8월부터 오디오 조직 구성원과 함께 개발했습니다. 단계별 사용법 가이드와 소개 발표 자료, 도움말 챗도 직접 만들었습니다.
