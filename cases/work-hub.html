Problem문제

The request was a bot. The problem was everything after it.

The audio team takes sound orders from 15 studios across 33 projects. Orders and the work that follows them lived in Jira, spreadsheets, Trello and Slack Lists.

The request was a Slack bot that tidies up incoming orders. But when I talked with the team, the hard part was what happened after an order arrived: splitting the work and keeping deadlines in view. A bot built exactly to the request would have been one more bot nobody used.

요청은 봇이었지만, 문제는 그다음에 있었다

오디오 조직 22명은 15개 스튜디오, 33개 프로젝트에서 사운드 발주를 받습니다. 발주와 그 뒤의 업무가 Jira·시트·Trello·Slack List에 흩어져 있었습니다.

요청은 발주를 정리해 주는 Slack 봇이었습니다. 그런데 현업과 이야기해 보니 정작 어려운 일은 발주를 받은 뒤 일을 나누고 마감을 챙기는 쪽이었습니다. 요청대로만 만들었다면 쓰이지 않는 봇이 하나 늘었을 것입니다.

Solution해결

What I built, and what I threw away만든 것과 버린 것

  1. Redefine the scope

    Widened the order bot into a hub that covers the flow after intake, from splitting the work to tracking it.

  2. Connect where the work already happens

    Synced Jira status per studio, and let people register tasks from Slack, where an LLM drafts the task from the message.

  3. Turn the team's words into design rules

    Things the team said became the rules for every screen:

    "Don't open a window to change one value."
    "No confirmation dialog for anything that can be undone."

  4. Drop what didn't fit

    I had put real work into a conversational ordering bot. After talking it through with the team, I removed it and rebuilt intake as Slack message shortcuts.

  5. Keep it moving after launch

    Added an MCP server so agents can work with tasks. Issues the team leaves become pull requests written by Claude Code, and a person reviews and merges them. Feedback is logged as decision records and applied every day.

  1. 범위를 다시 정의

    발주 정리 봇을, 발주 이후 일을 나누고 챙기는 흐름까지 다루는 허브로 넓혔습니다.

  2. 일하던 자리에 연결

    스튜디오별 Jira 상태를 동기화하고, Slack 메시지에서 LLM이 일감 초안을 써 주는 등록 방식을 붙였습니다.

  3. 현업의 말을 설계 원칙으로

    현업과 나눈 말을 그대로 화면 설계 원칙으로 삼았습니다.

    "값 하나 고치려고 창을 열지 않는다."
    "되돌릴 수 있는 일에는 확인창을 띄우지 않는다."

  4. 맞지 않는 건 걷어내기

    공들여 만든 대화형 발주 봇이 있었지만, 현업과 논의한 뒤 걷어내고 메시지 숏컷 방식으로 다시 만들었습니다.

  5. 출시 뒤에도 계속 굴러가게

    에이전트가 일감을 다룰 수 있도록 MCP 서버를 붙였습니다. 현업이 남긴 이슈는 Claude Code가 PR로 만들고 사람이 검토해 머지합니다. 피드백은 결정 기록으로 남겨 매일 반영합니다.
