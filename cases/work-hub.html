Architecture구조

Problem문제

The audio team of 22 takes sound orders from 15 studios across 33 projects. Orders, and the work that follows them, were split across Jira, spreadsheets, Trello and Slack Lists. Keeping all of it in sync took an estimated 120 hours of coordination a year.

I was first asked for a Slack bot that tidies up incoming orders. Talking it through with the team, I found the harder part came after an order arrived: splitting the work and keeping track of deadlines. A bot built only to the request would have been one more bot nobody used.

오디오 조직 22명은 15개 스튜디오에서 33개 프로젝트의 사운드 발주를 받습니다. 발주와 그 뒤의 업무는 Jira, 시트, Trello, Slack List에 나뉘어 있었고 이를 맞추는 커뮤니케이션에 연 120시간 정도가 들었습니다(추정).

처음 받은 요청은 발주를 정리해 주는 Slack 봇이었습니다. 현업과 이야기해 보니 정작 어려운 일은 발주를 받은 다음, 일을 나누고 마감을 챙기는 쪽이었습니다. 요청대로 봇만 만들었다면 쓰이지 않는 봇이 하나 더 생겼을 겁니다.

Solution해결

So I widened the bot into a hub that covers what happens after intake, from splitting the work to tracking it. Jira status syncs with the hub per studio. People register tasks straight from a Slack message, and an LLM writes the first draft of the task.

The screen rules came from things the team said while we worked:

"Don't open a window to change one value."
"No confirmation dialog for anything that can be undone."

I had spent real effort on a conversational ordering bot. After discussing it with the team I removed it and rebuilt intake as Slack message shortcuts.

To keep the hub moving after launch, I added an MCP server so agents can work with tasks. When the team leaves an issue, Claude Code turns it into a pull request and a person reviews and merges it. Feedback goes into decision records and gets applied every day.

봇 대신 발주를 받은 뒤 일을 나누고 마감을 챙기는 데까지 다루는 허브를 만들었습니다. 스튜디오별 Jira 상태는 허브와 동기화됩니다. Slack 메시지에서 바로 일감을 등록하면 LLM이 초안을 써 줍니다.

화면 설계 원칙은 함께 일하며 현업이 한 말에서 가져왔습니다.

"값 하나 고치려고 창을 열지 않는다."
"되돌릴 수 있는 일에는 확인창을 띄우지 않는다."

공들여 만든 대화형 발주 봇도 있었습니다. 현업과 논의한 끝에 걷어내고 메시지 숏컷 방식으로 다시 만들었습니다.

출시 뒤에도 허브가 계속 고쳐지도록 MCP 서버를 붙여 에이전트가 일감을 다룰 수 있게 했습니다. 현업이 이슈를 남기면 Claude Code가 PR을 만들고 사람이 검토해 머지합니다. 피드백은 결정 기록으로 남겨 매일 반영합니다.
